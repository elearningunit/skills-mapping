# קולט המיפויים (Google Sheets) – גרסה 2

הקולט הוא גיליון Google עם סקריפט. כשמרצה לוחץ באתר על **"שליחה לרשות"**, המיפוי נכתב כשורה בלשונית **מיפויים**.
רק מי שהגיליון משותף איתו רואה את הנתונים.

## מה הקולט עושה

| מצב | מה קורה |
|---|---|
| דיווח תקין | נשמר אוטומטית, `status = valid`, ונספר בחישובים |
| שיוך פקולטה–מחלקה לא מוכר, ערך חריג, ציון שאינו תואם לתשובות | **נשמר** ומסומן `flagged`. לא נספר עד הכרעה |
| חשד לכפילות: אותו מרצה, קורס, מחלקה, שנה אקדמית ושנה בתואר, במזהה אחר | **נשמר** ומסומן `flagged` עם `possible_duplicate:<מזהה>`. הדיווח הראשון נשאר תקין |
| שליחה חוזרת של אותו מיפוי | מעדכנת את השורה. `created_at` לא משתנה, ו-`submissions` עולה ב-1 |
| בקשה שאינה מיפוי (JSON שבור, מזהה לא תקין, מעל 20KB) | נדחית ולא נשמרת |
| שליחה מהירה מדי (אותו מיפוי בתוך 10 שניות, או מעל 60 בדקה) | נדחית. המרצה מתבקש לנסות שוב |
| השדה הנסתר נגד בוטים מולא | לא נשמר דבר |

כל קבלה ועדכון נרשמים בלשונית **יומן**. הנתונים המקוריים לעולם אינם נמחקים.

**עמודות הניהול** נמצאות בסוף לשונית "מיפויים":

| עמודה | פירוש |
|---|---|
| `created_at` | זמן היצירה. לא משתנה |
| `submissions` | מספר השליחות |
| `status` | `valid` / `flagged` / `excluded` |
| `flags` | סיבות הסימון |
| `dup_key` | מפתח הכפילות |
| `decision` | החלטת הרשות: `included` או `excluded`. תמולא מממשק הרשות. עד אז אפשר לכתוב אותה ידנית בגיליון |

## שדרוג מגרסה 1 (הגיליון הקיים) – כ-10 דקות

1. **לפתוח את הסקריפט:** פותחים את הגיליון ← **תוספים ← Apps Script**.
2. **להחליף את הקוד:** מוחקים את כל הקוד ב-`Code.gs`, ומדביקים את התוכן של
   https://github.com/elearningunit/skills-mapping/blob/main/collector/Code.gs
   (כפתור ההעתקה שליד "Raw"). שומרים (Ctrl+S).
   **אין צורך לערוך שום שורה בקוד.** כתובת המייל עוברת להגדרות (שלב 3).
3. **להגדיר את כתובת המייל:**
   - בסרגל הימני לוחצים על גלגל השיניים, **הגדרות הפרויקט** (Project Settings).
   - יורדים ל**מאפייני סקריפט** (Script Properties) ← **הוספת מאפיין סקריפט**.
   - **מאפיין:** `NOTIFY_EMAIL`. **ערך:** הכתובת, או כמה כתובות מופרדות בפסיק. לוחצים **שמירת מאפייני הסקריפט**.
4. **להסב את הנתונים הקיימים:**
   - חוזרים לעורך (סמל `< >`).
   - ברשימת הפונקציות בוחרים **migrate** ולוחצים **הפעלה**. אם מתבקש אישור הרשאות, מאשרים.
   - בגיליון יתווספו עמודות הניהול ולשונית **יומן**, וכל השורות הקיימות יקבלו סטטוס.
   - אפשר להריץ שוב בלי נזק.
5. **בדיקת מייל (לא חובה):** בוחרים **testNotification** ← **הפעלה**.
6. **לפרסם:** **פריסה ← ניהול פריסות** ← עיפרון ← **גרסה: גרסה חדשה** ← **פריסה**.
   **לא** "פריסה חדשה": כך הכתובת נשארת זהה, ואין צורך לשנות דבר באתר.
7. **לבדוק:** פותחים את כתובת הקולט בדפדפן. אמור להופיע `"version":2`.

## התקנה חדשה (גיליון חדש)

1. מתחברים לחשבון הרשות ונכנסים ל-**https://sheets.new**.
2. **תוספים ← Apps Script**, ומדביקים את `Code.gs` כמו בשלב 2 למעלה.
3. מגדירים את `NOTIFY_EMAIL` כמו בשלב 3.
4. מריצים **setup**: נוצרות הלשוניות "מיפויים" ו"יומן". מאשרים הרשאות. אם מופיע "Google לא אימתה את האפליקציה": **מתקדם ← מעבר אל… ← אישור**.
5. **פריסה ← פריסה חדשה** ← גלגל שיניים ← **אפליקציית אינטרנט**:
   - **הפעלה בתור: אני**
   - **למי יש גישה: כל אחד**

   "כל אחד" נדרש כדי שמרצים יוכלו לשלוח בלי להתחבר. הכתובת רק מקבלת מיפויים, ואינה מחזירה נתונים.
6. מעבירים את כתובת ה-`/exec` למפתח, שיעדכן אותה ב-`src/config/collection.ts`.

## פרטיות

- הגיליון מכיל שמות מרצים. משתפים אותו רק עם צוות הרשות, ולא ב"כל מי שיש לו את הקישור".
- ההודעה במייל אינה כוללת את שם המרצה.
- כתובת הקולט גלויה בקוד האתר. לכן הקולט בודק כל שליחה, מגביל קצב, ומסמן לבדיקה כל דבר חריג.

## למפתחים

- רשימת הפקולטות והמחלקות בקוד נוצרת אוטומטית: `npm run sync:collector`. בדיקה נכשלת אם היא שונה מרשימת האתר.
- הבדיקות (`tests/collector.test.ts`) מריצות את `Code.gs` מול גיליון מדומה, שמתנהג כמו Google Sheets: ממיר תאריכים ומספרים, ומתייחס לגרש בתחילת ערך כסימון לטקסט.
